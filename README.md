# MAXBALL EDTECH

Қазақша ашық кері байланыс алаңы. Next.js, React, TypeScript, PostgreSQL; жария ортада Supabase Auth және private Storage, орналастыру Vercel-де.

## Жергілікті Іске Қосу

Node.js 24 және npm қажет. Docker міндетті емес.

```sh
npm ci
npm run dev
```

Мекенжай: http://127.0.0.1:3000. Порт бос болмаса, `npm run dev -- --port 3001`.

`DATABASE_URL` берілмеген әзірлеу ортасында PGlite нақты PostgreSQL деректерін `.local/postgres/` ішінде сақтайды. Файлдар `.local/uploads/` ішінде. Ойдан алынған курстар, оқытушылар және профильдер тек осы ортаға енгізіледі. Сол жақ мәзірдің «Сынақ ортасы» тізімі рөлдерді тексеруге арналған. Email-ды растау мен қалпына келтіру де тек осы ортада хат жібермейтін сынақ сілтемелерімен орындалады.

`.local/`, `.env*`, құпия кодтар және кілттер Git-ке кірмейді. Деректер бетті жаңартқанда жоғалмайды. Жария ортада жергілікті режим мен демо рөлдер автоматты түрде өшеді; бұлттық дерекқор жоқ болса, қолданба қателікпен тоқтайды.

## Тексеру

```sh
npm run typecheck
npm test
npm run build
```

Іске қосылған жергілікті серверге арналған қосымша тексеру:

```sh
npm run test:http
```

Соңғы команда сынақ аккаунтын жасайды және тек жергілікті демоға арналған. Толық нәтиже: [_docs/verification.md](_docs/verification.md).

## Жария Орта

Нақты бұлттық қызметтер әзірге қосылмаған. Төмендегі әрекеттер қорғалған орта мәндері енгізілгеннен кейін ғана орындалады; олар жергілікті сайтты қарау үшін қажет емес.

1. Осы қолданбаға арналған Supabase жобасын пайдалану. Деректер аймағын, қызмет тарифтерін және резервтік көшірмелерді иесімен келісу.
2. `.env.example` ішіндегі айнымалыларды қорғалған `.env.local` немесе қызметтің Environment Variables бөліміне енгізу. Құпия мәндерді чатқа, репозиторийге немесе скриншотқа шығармау. `APP_SECRET` және `JOBS_SECRET` бөлек, криптографиялық кездейсоқ кемінде 32 таңбалы мәндер болуы керек.
3. `DATABASE_URL` үшін Supabase-тің серверлік pooler байланысын қолдану. TLS сертификаты қатаң тексеріледі. Қажет болса, провайдердің CA сертификатын `DATABASE_SSL_CA` арқылы беру; сертификатты тексеруді өшірмеу.
4. Бос жобаға `npm run setup -- migrate`, одан кейін `npm run setup -- storage` орындау. Біріншісі SQL схемасын және рұқсаттарды жасайды, демо деректерді қоспайды; екіншісі MIME шектеуінсіз, 20 МБ шегі бар private bucket дайындайды. SQL миграциясы checksum бойынша бір рет қолданылады.
5. Supabase Auth-та email растауын және нақты `APP_URL` доменіне рұқсат етілген redirect URL-дерді баптау. Auth-тың тіркелу, шақыру және қалпына келтіру хаттарына SMTP бөлек бапталады.
6. Ресми жауап хаттарына `SMTP_HOST/PORT/USER/PASS/MAIL_FROM` енгізу. Gmail қолданылса, жеке App Password не сәйкес пошта провайдері қажет. Жіберуші: `maksat.workspace@gmail.com`.
7. `OWNER_EMAIL=maksat.workspace@gmail.com`, нақты `OWNER_NAME` және `OWNER_PHONE` беріп, `npm run setup -- owner` орындау. Бастапқы басшылық профилі дайындалады; шақырудағы құпиясөзді иесі өзі орнатады. Басқа басшылық бар болса, құрал жаңа иені автоматты қоспайды.
8. Жабық GitHub репозиторийін Vercel-ге қосып, қорғалған айнымалыларды енгізу, `npm run build` арқылы жариялау. `APP_URL` нақты HTTPS доменіне сәйкес болуы керек. Preview ортасын production дерекқорына қоспау.
9. Supabase Vault-та `maxball_app_url`, `maxball_jobs_secret` мәндерін сақтау; `pg_cron`, `pg_net` қосып, [schedule.example.sql](supabase/schedule.example.sql) тапсырмасын баптау. Ол қорғалған `/api/jobs` мекенжайына POST жібереді. Кілт URL-ге немесе ашық cron мәтініне жазылмайды. [Ресми нұсқаулық](https://supabase.com/docs/guides/functions/schedule-functions).
10. ИИ провайдері мен мәтін жіберу шарттарын келісіп, `AI_API_URL/KEY/MODEL` енгізу. URL OpenAI-compatible chat completions JSON келісімін қолдауы керек. Жалған нәтиже қайтарылмайды: кілттер жоқ кезде тапсырмалар кезекте қалады, қолмен модерация жұмыс істейді.
11. Нақты ортада email жеткізу, кіру, >4.5 МБ файлдың Storage-қа тікелей жүктелуі, рөлдер, RLS, ИИ сапасы және резервтен қалпына келтіру бөлек тексеріледі. Өшірілген деректердің backup сақтау мерзімі 30 күннен аспайтынын растау керек.

Фондық тапсырмалар екі-екіден алынады, уақытша қате 5 минуттан кейін қайталанады, 5 әрекеттен кейін `failed` күйінде қалады. Оператор `private.jobs` ішіндегі тек сәтсіз тапсырмалардың күйі мен санын бақылайды; шифрланған хат мазмұны қолданба рөлдеріне берілмейді. Хат SMTP-ге жеткеннен кейін байланыс үзілсе, дәл бір рет жеткізу кепілдігі жоқ.

Жүктеп алуға берілген Storage сілтемесі 60 секундқа жарамды; жасыру жаңа сілтемелер беруді бірден тоқтатады. Жартылай жүктелген файлдар 24 сағаттан кейін тазаланады. Жүктемені, сақтау шығынын және сыртқы қызмет лимиттерін жариялау кезінде бақылау қажет.

`APP_SECRET` ауыстырылса, ескі шифрланған серверлік сессияларды және кезектегі email тапсырмаларын жоспарлы түрде тазалау не ескі кілтпен қайта шифрлау керек. Жай ауыстыру ескі сессияларды оқылмайтын етеді.
