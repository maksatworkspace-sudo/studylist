# MAXBALL EDTECH: архитектура

Күні: 2026-10-19.

Мәртебесі: 2026-10-20 жергілікті нұсқа іске асырылды. Supabase, email, ИИ және Vercel-дің нақты ортадағы қосылуы бөлек аяқталады. Соңғы тексерулер [verification.md](verification.md) құжатында.

Негізі: [талаптар](plan.md) және [2026-10-19 шешімдері](decisions-2026-10-19.md). Өнім ережелері бойынша жоспар басым; бұл құжат сол ережелерді іске асыру тәсілін сипаттайды.

## 1. Таңдау және себебі

Таңдалған нұсқа: **Next.js + TypeScript + Supabase**, орналастыру платформасы **Vercel**.

Алғашқы ұсыныс Laravel + Livewire + PostgreSQL болған. Кейін қолданушы Vercel арқылы орналастыруды таңдады. Осы жаңа шектеуге сай технология ауыстырылды: бір Next.js жобасы интерфейс пен серверлік әрекеттерді қамтиды; Supabase дерекқорды, аккаунттарды және файлдарды сақтайды.

Vercel-де PHP үшін community runtime бар, бірақ Laravel-дің тұрақты worker-ін және сервердегі файлдарды сақтауды бөлек ұйымдастыру қажет болар еді. Бұл жоба үшін Vercel-ге арналған Next.js интеграциясын таңдау орналастыруды ықшамдайды. [Vercel runtimes](https://vercel.com/docs/functions/runtimes), [Supabase және Vercel](https://vercel.com/marketplace/supabase/supabase).

| Қабат | Таңдалған құрал | Мақсаты |
| --- | --- | --- |
| Қолданба | Next.js App Router, React, TypeScript | Беттер, серверлік әрекеттер, тексерілетін дерек түрлері |
| Интерфейс | Tailwind CSS, Lucide белгішелері | Қазақша бейімделетін интерфейс |
| Дерекқор | Supabase PostgreSQL | Негізгі деректер, байланыстар, статистика, транзакциялар |
| Аккаунттар | Supabase Auth, cookie арқылы серверлік сессия | Email және құпиясөз, email растау, қалпына келтіру |
| Файлдар | Supabase Storage, private bucket | Құқықтары тексерілетін тіркемелер |
| Фондық жұмыс | PostgreSQL `private.jobs`, Supabase Cron + pg_net, Next.js worker route | Email жеткізу, ИИ тексеруі, сәтсіз тапсырмаларды қайталау |
| Орналастыру | Vercel | Next.js веб-қолданбасын жариялау |
| Тестілеу | Vitest, PGlite PostgreSQL, HTTP және браузердегі Playwright/CUA тексеруі | Ережелер, шектеулер, интерфейс және толық сценарийлер |

Нұсқалар `package.json` және `package-lock.json` ішінде бекітілген. Жергілікті деректерге PGlite қолданылады; жария орта Supabase PostgreSQL-де қалады. Қосымша Redis, бөлек worker қолданбасы немесе Edge Function қажет емес.

## 2. Құрылым

Бір Git репозиторийі және бір Next.js қолданбасы болады. Браузер бетті ашады; сервер сессияны, рөлді және нақты жазбаға құқықты тексеріп, Supabase-пен жұмыс істейді.

Негізгі жауапкершіліктер:

- Ашық жазбалар: оқу, іздеу, сүзгілеу, жіберу және бөлісу.
- Автордың өтініші: аккаунтпен немесе қонақтың нөмірі мен құпия коды арқылы рұқсат етілген әрекеттер.
- Қауымдастық: талқылау, қолдау, сақтау және оқытушы бағалары.
- Басқару: ресми жауап, мәртебелер, модерация, қызметкерлер мен анықтамалықтар.
- Есептер: тек әкімші мен басшылыққа арналған статистика.
- Фондық тапсырмалар: email және ИИ-модерация.

Бұл шекаралар бір жобаның ішіндегі жауапкершіліктерді бөледі. Қосымша микросервистер, жеке API жобасы немесе жеке әкімшілік қолданба қажет емес. Қызметкерлерге арналған беттер сол қолданбада рөлмен қорғалады.

## 3. Деректерді сақтау

| Деректер | Құрылымдық шешім |
| --- | --- |
| Профильдер мен рөлдер | Auth аккаунтынан бөлек профиль; аты-жөні, email, телефон және сервер бақылайтын рөл |
| Курстар мен оқытушылар | Басшылық басқаратын тізімдер; оқытушы аккаунтын қосу оқытушы тізімімен байланыстырылады |
| Жазбалар | Түрі, тақырыбы, мәтіні, нысаны, жариялау таңдауы және модерация күйі |
| Автордың жеке қолжетімділігі | Жазбаны аккаунтпен не қонақтың құпия кодымен байланыстыратын, жария API-ға ашылмайтын бөлек деректер |
| Мәселелер мен ұсыныстар | Түріне сай мәртебе, ұсыныстың нәтижесі және өзгерістер тарихы |
| Жауаптар мен талқылау | Ресми жауаптар бөлек; талқылау пікірлері мен бір деңгей жауаптар |
| Қолдау мен сақтау | Қолданушы-жазба байланыстары; қайталанудан қорғайтын бірегей шектеулер |
| Оқытушы бағалары | Қолданушы-оқытушы жұбына бір баға; 1-5 мәні және мәтіндік пікір |
| Тіркемелер | Файл Storage-та; метадерегі, көлемі және жазбамен байланысы PostgreSQL-де |
| Хабарламалар | Оқиға, алушы және оқылғаны туралы белгі; жеке авторға қатысты байланыстар жабық сақталады |

Бір оқытушыға қайталап баға беру бұрынғы бағаны жаңартады. Бірегейлік пен шектер серверде де, дерекқорда да тексеріледі.

Мәртебені өзгерту, тарихқа қосу және соған қатысты деректерді сақтау бір транзакциямен орындалады. Автордың өзгертуі мен әкімшінің ресми жауабы қатар келсе, құқық транзакция ішінде қайта тексеріледі.

Статистика сұрау кезінде негізгі деректерден есептеледі. Уақыттар UTC-де сақталады; экрандар, күн шектері мен айлық кезеңдер Asia/Almaty уақыт белдеуін қолданады. Қазіргі шағын орталық нұсқасы лентаны PostgreSQL-ден алып, мәтіндік іздеу мен сүзгіні браузерде орындайды. Үлкен лента үшін SQL пагинациясы мен серверлік іздеу қажет болады; жеке іздеу сервисі енгізілген жоқ.

## 4. Құқықтар және анонимділік

Аккаунтқа кіру үшін email және құпиясөз қолданылады; email расталады. Профильге телефон міндетті, SMS растауы қажет емес. Қонақтың жазба жіберуі тіркелуге тәуелді болмайды.

Құқықтар екі жерде тексеріледі: серверлік әрекеттерде және PostgreSQL рұқсаттарында. Браузерден берілген рөл, автор идентификаторы немесе батырманың көрінуі рұқсат дәлелі болып саналмайды. Ашық кестелерде RLS қосылады. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

Анонимділік үшін:

- Ашық жазбаның жауабы автордың аккаунт идентификаторын, email-ын, телефонын немесе жеке байланысты қамтымайды.
- Авторға қолжетімділік пен қалпына келтіру деректері бөлек жабық схемада сақталады; олар Data API арқылы тікелей ашылмайды.
- Анонимді жазбаның иесін тексеру мен оған хабарлама жіберуді сервер атқарады. Әкімші мен басшылық бұл байланысты ала алмайды.
- Аккаунттарды басқару беттері анонимді жазбалармен байланысты, кері сілтемелерді немесе сол байланысты ашатын сүзгілерді бермейді.
- Ашық тізімдер, басқару беттері және есептер нақты рұқсат етілген өрістерді ғана қайтарады; модельдерді түгел браузерге жіберуге болмайды.
- Журналдарға, аналитикаға және қате хабарламаларына құпия кодтар, қалпына келтіру токендері немесе анонимді авторды жазбамен байланыстыратын деректер жазылмайды.
- Толық серверлік кілт браузерге берілмейді. Оның қолданылуы нақты қызметтік әрекеттермен шектеліп, әр сұраныстың рұқсаты тексеріледі.

Басшылық қолданбадағы рөл болып қалады; ол дерекқордың техникалық иесіне тең емес. Бұл архитектура қолданбадағы барлық рөлден анонимді авторлық байланысты жасырады; инфрақұрылым кілттерін иеленушіге қарсы криптографиялық анонимділік уәдесін бермейді.

## 5. Қонақтың құпия коды

Жария өтініш нөмірі және кездейсоқ, болжауға қиын құпия код жасалады. Дерекқорда кодтың тек қорғалған хэші сақталады; код URL-ге, журналға немесе ашық браузер қоймасына жазылмайды.

Дұрыс нөмір мен код қысқа мерзімді, HttpOnly cookie арқылы сол өтінішке ғана қолжетімділік береді. Қате кодты тексеру әрекеттеріне жиілік шектеуі қойылады. Код жазба бар кезде жарамды; email арқылы ауыстырғанда ескісі жарамсыз болады.

Қалпына келтіру тек алдын ала қалдырылған email арқылы, бір рет қолданылатын мерзімді сілтемемен орындалады. Қалпына келтіру email-ы қолданба рөлдеріне ашылмайды. Email мен код екеуі де жоқ болса, қолжетімділік қалпына келтірілмейді.

## 6. Файлдарды жүктеу

Бір жазбаға ең көбі 5 файл, жиынтық көлемі 20 МБ. Файл түріне өнімдік шектеу қойылмайды.

Сервер уақытша жүктеу рұқсатын береді; файл браузерден Supabase Storage-қа тікелей жіберіледі. Vercel Function арқылы үлкен файл тасымалданбайды: оның сұраныс көлемінің шегі 4.5 МБ. [Vercel шегі](https://vercel.com/docs/functions/limitations).

Сервер нақты сақталған файлдардың көлемін, санын, иесін және жазбаға тиесілігін тексереді. Бір мезеттегі жүктеулер 20 МБ шегін айналып өтпеуі тиіс. Барлық таңдалған файл жүктелгенше немесе сәтсізі алынып тасталғанша жіберу аяқталмайды; енгізілген мәтін сақталады.

Файлдар кездейсоқ жолдармен private bucket-те сақталады. Жүктеп алу алдында жазбаның көрінуі тексеріліп, қысқа мерзімді сілтеме беріледі. Кез келген файлды қабылдау белсенді HTML не басқа орындалатын мазмұнды сайт доменінде іске қосуға рұқсат бермейді; күмәнді түрлер жүктеп алу ретінде беріледі. [Storage қолжетімділігі](https://supabase.com/docs/guides/storage/buckets/fundamentals).

Жасыру тіркемелерге жаңа қолжетімділікті тоқтатады. Толық өшіру пікірлер мен файлдарды жою тапсырмасын да қамтиды; жою аяқталғанша файлға қолжетімділік берілмейді. Резервтік көшірмелердегі сақтау мерзімі 30 күннен аспауы үшін нақты провайдер баптауы жариялау алдында тексеріледі.

## 7. Хабарламалар және фондық тапсырмалар

Сайт ішіндегі хабарлама негізгі әрекетпен бірге сақталады. Email тапсырмасы немесе ИИ тексеруі PostgreSQL транзакциясында тұрақты кезекке қосылады.

Нақты іске асыруда тұрақты кезек `private.jobs` кестесінде, тапсырманы алу `FOR UPDATE SKIP LOCKED` арқылы орындалады. Supabase Cron + pg_net қорғалған `/api/jobs` бағытын шақырады. Екі тапсырма өңделеді; 5 минуттық қайта талпыныс, ең көбі 5 әрекет. Бұл бастапқы Queues/Edge Functions сызбасын ықшамдайды. Email сыртқы қызметке жіберілген сәтте байланыс үзілсе, жеткізудің дәл бір рет болуына кепілдік берілмейді; тұрақты Message-ID қолданылады. [Жоспарлау үлгісі](../supabase/schedule.example.sql), [ресми құжат](https://supabase.com/docs/guides/functions/schedule-functions).

Авторға ресми жауап туралы сайт ішінде және email арқылы хабарланады. Әкімші мен басшылық жаңа жазба туралы тек сайт ішінде хабарлама алады. Мәртебе ауысуы мен жаңа талқылау пікірі авторға қосымша хат жібермейді.

Жіберуші мекенжайы: `maksat.workspace@gmail.com`. Оны қолдану үшін Gmail-дің тиісті авторизациясы немесе SMTP App Password бапталуы қажет; жай email мекенжайы хат жіберуге жеткіліксіз. Құпия мәндер тек қызметтердің қорғалған баптауларында сақталады. [Google App Password](https://support.google.com/mail/answer/185833).

Жергілікті режимде растау және қалпына келтіру сілтемесі тек демо интерфейсіне қайтарылады; SMTP хат жіберуі өшірулі. Автотесттерде пошта тасымалдаушысы алмастырылады. Демо аккаунттарға нақты email жіберілмейді.

## 8. ИИ-модерация

Жазбалар мен талқылау пікірлерінің бірден жариялануы сақталады. ИИ жарияланған мәтіндегі ықтимал спам мен қорлауды фондық режимде тексеріп, әкімшіге белгі береді. Бастапқы архитектуралық шешім: жасыру мен толық өшіруді себебін көрсетіп әкімші орындайды; ИИ өзі толық жоймайды.

ИИ провайдеріне тек тексерілетін мәтін жіберіледі; профиль, авторлық байланыс, email, телефон, құпия код және файлдар бөлек қоса жіберілмейді. Мәтіннің өзіндегі айқын байланыс деректерін азайту қарастырылады. Қолданушы мәтіні нұсқау ретінде орындалмайды; ИИ нәтижесі тек шектеулі модерация белгілері ретінде қабылданады.

Сын пікір мен төмен баға өздігінен спам болып саналмайды. Провайдер қатесі жазбаны жоғалтпайды: тексеру кезекте қалады, қолмен модерация қолжетімді болады. Қайталанған жіберуден қорғау мен жиілік шектеуі ИИ-ден тәуелсіз жұмыс істейді.

Провайдер, модель және қызметтік кілт жариялау алдында таңдалып, қазақша спам және орынды сын мысалдарымен тексеріледі. Нақты ИИ интеграциясы дайын болмайынша, оны жұмыс істейді деп көрсетуге болмайды.

## 9. Дизайн және демо деректер

Дизайн бағыты: [TENEASY үлгісі](https://teneasy.vercel.app/TENEASY.dc.html). Бұл тек визуалдық референс. Оның сабақ картасы, тапсырмалары, XP жүйесі, лигалары немесе басқа оқу функциялары жобаға көшірілмейді.

Қолданылатын бағыттар: айқын бренд, сапалы иллюстрациялық фон, ашық жұмыс беттері, анық белсенді навигация және ықшам күй көрсеткіштері. Негізгі экран ашық кері байланыс тізімі болады. Мәтін, сүзгілер мен басқару беттері оқуға және күнделікті жұмысқа ыңғайлы етіп жасалады; қонаққа жазбаларды көру үшін кіру қабырғасы қойылмайды.

Логотип: [maxball-logo.png](assets/maxball-logo.png). Ол `imagegen` арқылы жасалған жаңа M және жұлдыз белгісі; бренд атауы интерфейсте бөлек мәтінмен беріледі. Генерация сипаттамасы [шешімдер құжатында](decisions-2026-10-19.md#логотип) сақталған.

Демо курстар, оқытушылар және басқару аккаунттары ойдан жасалады. Демо email-дар `.example` доменін қолданады, құпиясөздер Git-ке сақталмайды. Демо деректер өндірістік ортаға автоматты енгізілмейді; нақты алғашқы басшылық аккаунты бөлек қорғалған рәсіммен ашылады.

## 10. Тестілеу

- Vitest: мәртебелер, статистика формулалары, 1-5 шкаласы және серверлік тексерулер.
- PostgreSQL интеграциялық тесттері: бірегей бағалар, қатар келген әрекеттер, транзакциялар және рөлдерге сай RLS.
- Құпиялық тесттері: қонақ, қолданушы, оқытушы, әкімші және басшылық анонимді авторды API, профильдер, файлдар не есептер арқылы анықтай алмайды.
- Компонент тесттері: қазақша формалар, сүзгілер, қате хабарламалары және деректердің сәтсіз жіберуден кейін сақталуы.
- Playwright: қонақтың жіберуі мен кодпен оралуы; тіркелу; ресми жауап; мәселені қайта ашу; ұсыныстың нәтижесі; рейтинг; модерация; басқа құрылғыдағы сақталғандар.
- Файл тесттері: 5 файл және жиынтық 20 МБ шегі, үлкен файлдың тікелей жүктелуі, жартылай сәтсіздік және жасырудан кейінгі қолжетімділік.
- Интеграция тесттері: email қайта жіберу, қайталанған тапсырмалар және ИИ қызметінің істен шығуы.
- Экран тексеруі: мобильді және компьютер өлшемдері, пернетақта фокусы, мәтіннің сыйуы, суреттердің жүктелуі және басқару элементтерінің қабаттаспауын тексеру.

Жоғарыдағы тізім толық қабылдау бағытын сипаттайды; нақты орындалғандары мен нақты бұлтта әлі тексерілмегендері [verification.md](verification.md) құжатында бөлек берілген. Орнатылған PostgreSQL рұқсаттары PGlite-де тексерілді; бұл Supabase жобасындағы нақты RLS аудитінің орнына жүрмейді.

## 11. Іске қосу

Жергілікті орта: Node.js 24, жоба тәуелділіктері және дискіде сақталатын PGlite. Docker жоқ ортада да жұмыс істейді. Бір SQL схема жергілікті PostgreSQL және Supabase үшін қолданылады. Жергілікті авторизация кодты тексеруге арналған; жария ортада Supabase Auth міндетті.

Жариялау: жеке GitHub репозиторийі Vercel-ге қосылады; Supabase жобасында дерекқор, Auth, private Storage, кезек және жоспарланған тапсырмалар бапталады. Файлдар Vercel дискінде сақталмайды. Алдымен Vercel берген домен пайдаланылады; жеке домен кейін қосылады.

Жариялау алдында:

1. Жұмыс істейтін жергілікті нұсқа жоспардағы қабылдау өлшемдерімен тексеріледі.
2. Дұрыс GitHub аккаунты мен репозиторийдің жабықтығы тексеріледі.
3. Vercel және Supabase жобаларының иесі, бюджеті және деректер аймағы анықталады.
4. Кілттер қорғалған ортаға енгізіліп, email мен ИИ интеграциялары тексеріледі.
5. Миграциялар, email сілтемелерінің домені және алғашқы басшылық аккаунты бапталады.
6. Дерекқор мен файлдардың резервтік көшірмесі және қалпына келтіру рәсімі тексеріледі; 30 күндік өшіру талабы провайдер мүмкіндігімен сәйкестендіріледі.
7. Қызметтік қателер, сәтсіз кезек тапсырмалары және сақтау көлемі бақыланады.

Қолданушы Vercel және Supabase аккаунттары бар екенін, авторизация дайындайтынын растады. Нақты алғашқы басшылық email-ы `maksat.workspace@gmail.com`; аты-жөні мен телефоны алғашқы профильді ашқанда беріледі. Қызметтер бюджеті мен ИИ провайдері бекітілмеген; қызметкерлердің жалақысы бұл сайттың талабы емес және жарияланбайды. Қазіргі демо бұл қызметтер бапталды дегенді білдірмейді.

## Модерация жүйесі (2026-10-20, #25)

Кестелер (`store_migrations` v3): `reports` (PK: reporter_key|target_type|target_id —
бір адам бір мазмұнға бір шағым; guest кілттері серверден шықпайды), `moderation_log`
(әр модерация шешімі: модератор, әрекет, мақсат, себеп, ескі/жаңа күй, уақыт — FK жоқ,
өшірілген мазмұннан кейін де сақталады) және `comments.hidden/hidden_reason` (пікір
жасыру — постқа әсер етпейді).

Әрекеттер: `report` (барлық кірушіге, rate limit 10/600s IP бойынша, мазмұнды
жасырмайды), `setReportStatus` (тек менеджер: new → reviewing/resolved/dismissed),
`moderateComment` (тек менеджер: hide/restore/delete). Бар `moderate` әрекеті енді
аудит жазбасын қалдырады және қайта-жасыру/қайта-қалпына келтіру қателерін қайтарады.
Анонимдік: шағымдар мен журналда автордың деректері емес, мазмұн нөмірі/тақырыбы ғана
жүреді; reporter көрсетілімі — «Қонақ» немесе profil аты.

UI: «Модерация» парақшасы — Шолу/Шағымдар/Жасырылғандар/Тарих; шағым беру
диалогы пост пен пікірлерде; қиратушы әрекеттер Confirm диалогымен (нативті
confirm() алынып тасталды). Mock қызаете толық паритетке ие.
