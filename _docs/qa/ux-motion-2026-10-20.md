```sh
npx vitest run tests/qa-ownership.test.ts --reporter=dot
TEST_ADAPTER=sqlite npx vitest run tests/qa-ownership.test.ts --reporter=dot
```

Both commands exited 1: **10 failed, 6 passed, 16 total**, with no skipped cases.
Each invocation contains 13 adapter-backed domain tests and 3 mock-parity tests.
Memory uses a fresh Map store; SQLite uses the existing harness's fresh temporary
database. Synthetic identities only; no user preview, providers or actual data
were accessed. Browser execution was not performed by this QA role.

The seven adapter-backed failures demonstrate:

- Guest creation inserts an immediate grant.
- Direct edit succeeds without explicit unlock.
- Reopen succeeds without explicit unlock.
- Unlocking one post leaves another creation-time post editable.
- Authenticated code access has no separate registered-ownership DTO flag.
- Registered anonymous ownership lacks that same DTO flag.
- Recovery creates a new editing grant automatically.

Three mock tests likewise fail creation access, ownership separation and recovery
access. Six existing-boundary controls pass: bad codes, session rotation, expired
and revoked grants, hidden/replied-post restrictions, DTO secret exclusion, and
staged attachment token migration.

The first exploratory run also exposed an error in QA teardown: the Store
interface has no `close()` method. That invalid teardown was removed before the
two recorded RED runs; it is not an application bug or part of the above totals.
